Queued, never dropped

Send while the agent is working and your message queues behind the current turn. It is delivered when the agent goes idle, in the order you sent it. Interrupt, and the queue survives the switch.

The model picker sits on the same bar and shows which providers are actually reachable right now, not which ones you configured once.

Several working at once, in one project, side by side. Each is a real window with its own conversation, its own tool activity and its own approvals. One of them can be reading a file while another is running its tests.

They keep working when you look away

Switching view never interrupts an agent. A window you close is the only thing that stops it, and the Projects list keeps showing which project has work still running.

Every project runs its own daemon process, so one project stalling cannot freeze another.

Saves that cannot be lost

Saving is serialised, so a second save waits for the first rather than overwriting it. Changing project asks before it discards an unsaved buffer, and closing the window is held back until the file has actually reached disk.

The tree is windowed, not exhaustive: a project with three thousand files opens instantly instead of rendering three thousand rows.

Everything else

The rest of the window

The views above are the ones you spend time in. These are the ones you forget about until you need them.

Projects

Point Olympus at a folder and every project inside it appears. Search by name, path or stack, sort by recency or last edit, pin what matters, hide what you do not.

A project with an agent running is named on its row, not just labelled open.

Preview

Your development server, embedded beside the agent, so you can see the change land without leaving the window. Only loopback addresses are allowed, by design.

It opens itself when a run starts, and closes when you stop caring.

Terminal

A real shell against the project directory, not a simulated one. It is the same terminal the agent uses, so what it saw is what you see.

Output is selectable, which sounds trivial until you have needed to copy a command.

Models

Ollama, LM Studio, vLLM and llama.cpp are discovered on their usual ports, alongside whatever providers your opencode install already knows about.

Only models that answer right now are offered.

Approvals

Per project, ask or bypass. Edits and commands are separate decisions, because a command can change what the diff never showed.

Bypass is a choice you make per project, not a hidden default.

Skills

Whatever skills your opencode workspace exposes, listed in the sidebar and available to the agent without a prompt.

Nothing is invented: if the workspace has no skills, the panel says so.

The window is the argument.
