The short version

An agent is only useful if you can see it working.

Most coding agents live behind a single chat window: one conversation, one project, and a lot of trust that whatever changed is what you asked for. Olympus started from one disagreement with that — the work should be visible, and the decision to write it to disk should always be yours.

So Olympus is built around three things that do not bend: your projects stay on your machine, every edit waits for your approval before it reaches a file, and the application works the same whether or not you ever create an account — because there is no account to create.

It is independent software. Not a feature of a larger platform, and not a tier designed to funnel you somewhere else. One licence, paid once, for an application that keeps working.

What this means in practice

Three decisions we keep making the same way.

Local-first, by default

Olympus is built around models running on your own computer. A cloud provider is something you opt into through your agent's own configuration, never something Olympus adds on your behalf.

Nothing writes itself

An edit the agent proposes is a proposal, held in a diff, until you accept it. Shell commands ask separately, because they can change files too.

No account, no tracking

There is nothing to sign into and nothing phoning home. The application does what the page says it does, which is also why the page stays this plain.

Where it stands

Early, on purpose.

Olympus is at 0.1.0. That means the core is in place — per-project agents, a diff you have to click through, a live preview — and the rough edges are still being found and fixed in the open. The changelog is the honest record of that, including the things that did not work the first time.
