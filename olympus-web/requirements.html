Requirements

What you need first

Four things, and all of them are probably already on your machine. Then the caveat, which matters more than the four.

Home / Requirements

The list

Four prerequisites

Olympus does not fetch any of these for you and does not install anything behind your back.

  • Node 18 or newer. Check with node --version.
  • opencode available on your PATH. Check with opencode --version and see the note below about which version.
  • A model that already runs locally: Ollama, LM Studio, vLLM, llama.cpp, any loopback OpenAI-compatible server, or a provider configured inside opencode.
  • A project folder on your machine. Nothing is fetched for you.

Platforms

Intended targets for the Electron build. All three are built and tested. If one breaks on a new OS release, it breaks in the open and goes in the changelog.

macOS

Apple Silicon and Intel, as separate builds. Both are covered by the same licence. Apple Silicon is a first-class target, not Rosetta.

Windows

Windows 10 and Windows 11, 64-bit. Shipped as a signed installer.

Linux

64-bit, shipped as an AppImage. Other distributions will very likely work, but they are not what we test against.

All set? Work through the four steps, or read what is in the window first.

Compatibility

Olympus depends on somebody else’s project

This is the most important paragraph on the website, and it is here rather than in a footnote.

Olympus is a separate, third-party tool. It is not affiliated with, endorsed by, sponsored by or supported by the opencode project or its maintainers, and it does not speak for them. It is a GUI and a process supervisor for a program you already have installed.

Which means:

  • A working opencode on your PATH is a hard requirement. Olympus does not bundle it, install it, or keep a private copy. If it is not there, nothing starts.
  • opencode is evolving, and Olympus is coupled to its HTTP surface. Olympus supervises opencode serve and talks to it. When that interface changes, Olympus has to follow. Some versions will work. Some will not.
  • Known to work: 1.18.x. That is the line 0.1.0 was built and tested against, and the line the changelog records for every release. Check it before you upgrade opencode, not after.
  • Other versions are untested, not forbidden. Plenty of people will run something else and have it work. Olympus does not block you from trying.

What happens when a version does not fit

Olympus reads the opencode version at startup and checks it. When what it finds does not match what it was built against, it says so on screen, names the version it actually found, and explains what to do about it. It does not start a daemon it cannot supervise, and it does not degrade quietly into a half-working state that looks fine until you notice the wrong thing happened.

If you would rather not find out at startup, the version check is one line in the documentation, and pinning opencode to 1.18.x with whatever version manager you use is a perfectly reasonable thing to do.

What this means for the licence

Nothing good, which is why it is here. If a future opencode release breaks your working setup and we have not shipped a fix, that is a real cost to you and we cannot pretend otherwise. Two things limit it. First, the 14-day refund window means you find out before it matters. Second, your 0.x build keeps working: if a later opencode release stops working with 0.1.0, the version of opencode that does work with it is still installable, and we will have written down which one that is.

Nothing here is hidden, and nothing is guaranteed either. A security-conscious buyer should assume any app that wraps somebody else’s fast-moving agent will occasionally be behind. We would rather you buy knowing that than find out in month three.
