Security

What is actually true

Olympus is a local app that supervises a local agent. That is a much smaller attack surface than a service, but it is not zero, and this page is written to be checkable rather than reassuring.

Home / Security

The mechanisms

Four things the app does, concretely

Each of these is a property of the build, not a setting you can forget to turn on.

The page cannot open its own connections

The window runs with contextIsolation on, nodeIntegration off, and the Chromium sandbox enabled. The renderer has no Node integration and no direct route to the network: the packaged renderer ships with a strict Content-Security-Policy whose connect-src is 'self', so the only address it may reach is its own origin. Every model call, agent call and preview load is proxied through the main process, which decides what to connect to.

Each daemon gets a fresh, unguessable credential

Every opencode serve process Olympus starts is bound to 127.0.0.1 only — not to 0.0.0.0 and not to a routable interface — on a randomised high port, and is protected with HTTP basic auth using a random credential generated afresh for that launch. The credential is never written to a shared location and never reused, so another process on the machine or a web page in another application has to guess both the port and the credential.

Endpoints you add are restricted to loopback

Model servers and any endpoint you configure in the app are checked to be on loopback before they are used. You can point Olympus at 127.0.0.1, localhost or ::1; you cannot point it at a host out on the network from the in-app endpoint editor. Providers you have already configured inside opencode are a separate matter and are described below.

Writes are a decision, not a side effect

An edit made through the edit tool is a proposal. It stops in a diff viewer and stays there until you accept it; reject it and nothing is written. Shell commands ask separately, because a command can change files the edit tool never touched. Leaving a project folder, or an agent asking politely, is not a reason to accept anything.

The other half

What this does not protect you from

A security page that only lists strengths is a marketing page wearing a lanyard. Here is the other list, and it is longer.

opencode is somebody else’s software

Olympus supervises a process it does not ship. Whatever opencode does with your prompts, your repository and your keys is opencode’s behaviour, and we do not control it, audit it or stand behind it. Treat the agent as you would treat any other program you are running against your own source.

An agent on loopback is still an agent on loopback

The credential and the loopback binding make the daemon hard to reach by accident. They are not a claim that it cannot be reached, and they are not a claim that a running agent is harmless. Do not run one against a machine you would not hand the keys to.

Approving is a human process, not a technical control

Diff review works because you read the diffs. Under time pressure, on the tenth edit of an afternoon, approval degrades into a reflex. Olympus will not stop you clicking Accept on a destructive patch, because it cannot tell that you are not paying attention.

The shell is a shell

An approved command runs with your privileges, in your working directory, with your environment. Approval is the only gate in front of it.

Cloud providers are outside all of this

The loopback restriction applies to endpoints you add in Olympus. If you have configured a cloud provider inside opencode, then that traffic leaves the machine, and the Content-Security-Policy is not involved: it constrains the renderer, not the agent. This is the single most important thing to understand on this page.

No encryption claim

Traffic between Olympus and a local model server is ordinary HTTP on loopback. It is not end-to-end encrypted, and it does not need to be to stay on the machine, but we are not going to describe plain loopback HTTP as if it were a security feature.

And one thing we are not saying at all. We do not claim the daemon is unreachable. We do not claim opencode is secure. We do not claim there is end-to-end encryption, because there is not. The mechanisms on the previous page are real and specific; that is the entire claim.

Reporting

Found something?

Email, not a public issue. A public issue is a disclosure: it is indexed, it is cached, and it cannot be taken back.

  • Email security@example.com. Describe the problem, the build you are on, your operating system, and how to reproduce it. Plain text is fine and preferred.
  • You will get an acknowledgement. Realistically within a few days, from whoever maintains the app. There is no security team, so there is no response-time guarantee, and pretending otherwise would be the first dishonest thing on this site.
  • Ordinary bugs go in the open. If it is not exploitable — a crash, a wrong message, a model that will not load — a public issue is the right and welcome place for it. support@example.com also works.
  • No bug bounty. There is no programme and no reward. We will credit you in the changelog if you want that, on your terms including not at all.

What “local-first” means. It means Olympus has no server, no account and no telemetry, and that by default your prompts and your code stay on the machine and go to a model server you chose. It does not mean opencode is local, it does not mean nothing ever touches a network, and it does not extend to any model provider you have configured yourself. The privacy policy says the same thing without the marketing gloss.
