What it is for

Three questions it answers

A coding agent is only useful if you can tell what it is doing. Every part of Olympus exists to answer one of three questions.

Which project am I in?

Each project gets its own agent process. Switching projects never interrupts what another project's agent is doing, and busy state stays visible in the project tree.

What is the agent doing?

Streamed reasoning, tool-call cards with expandable output, an agent-output console, and a real interactive shell. The work is visible while it happens.

What changed?

Edits made through the edit tool pause in a diff viewer. Nothing is written to disk until you accept. Shell commands need a separate approval, because they can change files.

The second question

What is the agent doing?

This is the part that decides whether an agent is useful. Not its final answer. The work in between. Reasoning as it is produced, every tool call as a row you can open, and nothing written to your disk until you say so.

Questions

The ones worth asking first

If your question is not here, support@example.com is a real address and a person reads it.

Does it work offline?

Yes, with one condition: you need a model server running on the machine. If Ollama, LM Studio, vLLM or llama.cpp is up with a model loaded, Olympus never needs the network at all. It spawns its own local opencode serve, talks to it over loopback, and stops when you exit.

What it will not do is fetch anything for you. There is no model download, no account to create, and no telemetry endpoint to reach. If the model server is not running, Olympus says so and stops there rather than silently falling back to a cloud provider.

What does it cost?

$49 once, per person. Not per month, not per project, not per machine. The full breakdown is here, including what a future major version would cost.

You also need opencode and a model server. Those are separate costs, and they are the same whether you use Olympus or not.

Is there a subscription?

No, and there is not going to be one. The app has no server, so there is nothing a recurring payment would buy. The version you buy keeps running.

Updates inside the 0.x line are free and automatic. A future 1.0 would be a one-off upgrade at a price we will publish before it exists, and every 0.x build will keep working.

Is my code sent anywhere?

Not by Olympus. It has no server, no account system and no telemetry. Your prompts and your repository go to whatever model server you configured, which, for the setup this app is built around, is one running on your own machine.

Two honest caveats. If you configure a cloud provider inside opencode, then your prompts go to that provider, because that is what you asked for. And opencode is a separate project: what it does with your data is its business, not ours. The privacy policy says the same thing in more words.

What do I need installed?

Node 18 or newer, and opencode on your PATH. A model already running locally, and a project folder to point at. That is the whole list, and most people running local models already have all four.

The requirements page goes into it, along with the supported platforms.

Which model servers work?

Anything speaking the OpenAI API on loopback. In practice that is Ollama, LM Studio, vLLM and llama.cpp, all discovered automatically, plus any other local server you add by hand.

Providers already configured inside opencode appear in the model picker too, so an existing setup carries over without being re-entered.

Can I use a cloud provider?

Yes, if you have already configured one in opencode. Olympus will show it and let you pick it. It will not add one for you, and it will not ask you for a key. That stays entirely inside opencode’s own configuration.

Olympus is built for the local case and the preview pane, the model discovery and the loopback-only endpoints all assume it. Cloud models work, but they are not what this app is for.

What happens to my data if I uninstall?

Nothing, because there is nothing of ours to remove. The app keeps its project list, preferences and licence in your operating system’s normal application-data directory: ~/Library/Application Support/Olympus on macOS, %APPDATA%\Olympus on Windows, ~/.config/olympus on Linux. The privacy policy names the paths and the files.

Your projects, your code and your git history are yours and are never copied. If you want the app’s own settings gone, delete that one directory. Uninstalling the binary does not delete it, deliberately.

How does licensing work?

One purchase, one person. No activation server, because there is no server to activate against. The licence is validated offline against the key in your receipt, so the app works on a plane.

Commercial use is fine. Two machines per person. You may not redistribute the binary or resell it. The licence is the authoritative version and it is short.

What is the refund policy?

Fourteen days from purchase, no questions asked, no form. Email support@example.com and the money goes back. The full terms are here.

What happens if opencode changes underneath you?

This is the real risk, and we would rather name it than bury it. Olympus depends on a working opencode on your PATH, and opencode is evolving. Known to work with 1.18.x. Other versions may not.

When something does not line up, Olympus says so on screen and names the version it found, rather than failing quietly or pretending to work. The compatibility note has the detail, and the changelog records which versions each release was tested against.

Does it run on Apple Silicon?

Yes. Apple Silicon is a first-class target, not an emulation, and there is a separate build from the Intel one. Both are $49, one licence, two builds, and you can move between them.

How do I get help, and how do I report a security problem?

Ordinary bugs: support@example.com, or a public issue if you would rather have the fix in the open.

Security problems: email security@example.com instead. Please do not open a public issue for anything exploitable. A public issue is a disclosure. You will get an acknowledgement.
